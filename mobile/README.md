# Speakora â€“ Android app

React Native (0.88, new architecture, Hermes) client for the same Spring Boot backend the website uses. Same accounts,
same matchmaking, same WebRTC signalling. Voice only; calls are never recorded.

| Area | Implementation |
| --- | --- |
| Auth | Email + password. Access token in memory; refresh token in the Android Keystore (`react-native-keychain`), sent as `X-Refresh-Token` (the server returns it in the body only when `X-Client-Type: mobile`). |
| Voice | `react-native-webrtc`: one Opus audio track each way, ICE restart, TURN credentials fetched per call from `/api/calls/ice-servers`. Same state machine as the website (`src/features/call/CallContext.tsx`). |
| Background | A foreground service (type *microphone*, via notifee) keeps the microphone alive when you switch apps. Android 13+ asks for notification permission once. |
| Audio routing | `react-native-incall-manager` (earpiece / speaker / Bluetooth, audio focus, interruptions). |
| Screens | Welcome, sign in/up, forgot password, onboarding, home, talk (search, call, ended + feedback + block/report), topics, progress, speaking coach, history, settings (profile, account, privacy, notifications, blocked, delete account). |

## Requirements

* Node 22+, JDK 17+ (21 is fine), Android SDK with platform 36/37 and NDK 27.1.12297006 (Gradle installs the missing
  pieces on the first build when licences are accepted).
* A physical Android 8.0+ phone (API 26+) for real calls. Emulators cannot give you a meaningful microphone test.
  **Not verified here:** no emulator or device was available while this was built; the app compiles, type-checks and the
  logic is unit-tested, but nobody has yet made a call from it. Follow `docs/REAL_DEVICE_TEST.md` first.

## Point the app at your backend

```powershell
cd mobile
npm install
npm run set-api-url -- https://speak.your-domain.com   # production: https is mandatory
# local network testing (debug only): npm run set-api-url -- http://192.168.1.20:8080
```

**A phone connected by USB (recommended, survives hotspot and Wi-Fi changes):** the default address is `http://localhost:8080`, reached through the USB tunnel:

```
adb reverse tcp:8080 tcp:8080     # backend
adb reverse tcp:8081 tcp:8081     # Metro
```

Debug builds also remember a server address chosen on the welcome screen ("Developer: server settings"). At start-up they probe that saved address and the
built-in default, and use the first that answers, so a saved LAN or hotspot address that has gone stale no longer shows "Could not reach the server".
Release builds never probe: they always use the https address baked in by `set-api-url`.

The Android emulator reaches the host machine at `http://10.0.2.2:8080` (the default). Release builds block cleartext
HTTP; the script refuses non-local `http://` addresses. Debug builds also let you change the server on the welcome screen.

## Build an installable APK

```powershell
cd mobile
npm run typecheck ; npm test                       # TypeScript + Jest
cd android
.\gradlew.bat assembleDebug                        # android\app\build\outputs\apk\debug\app-debug.apk
```

Debug APK: signed with the public debug key, fine for your own phone, not for distribution.

### Release APK (signed with your own key)

```powershell
cd mobile\android
keytool -genkeypair -v -storetype JKS -keystore app\release.jks -alias esp-release -keyalg RSA -keysize 4096 -validity 10000
# create android\keystore.properties (gitignored):
#   storeFile=app/release.jks
#   storePassword=...
#   keyAlias=esp-release
#   keyPassword=...
.\gradlew.bat assembleRelease                      # android\app\build\outputs\apk\release\app-release.apk
```

**Back up `release.jks` and its passwords somewhere safe, outside the repository.** Android refuses to update an
installed app that is signed with a different key, so losing it means every user must uninstall first. A release build
without `keystore.properties` fails on purpose rather than falling back to the debug key.

## Publishing the release APK

See `docs/DEPLOYMENT.md` (Android app download): build with your real address, then `scripts\publish-android-apk.ps1` checks the signature and the baked-in address before copying it to the website's `downloads` folder.

## Install on your phone

1. Enable *Developer options* and *USB debugging* (or copy the APK over and allow installs from your file manager).
2. `adb install -r android\app\build\outputs\apk\debug\app-debug.apk`

